# 游戏状态管理 (Game State Management)

*Created: 2026-05-07*
*Status: Draft*
*Priority: MVP — Foundation Layer*
*Depends on: 无*
*Depended on by: 瞄准系统, 生命值系统, 关卡/楼层系统, 房间制战斗, 复活币系统, UI/HUD*

---

## 1. Overview

游戏状态管理系统负责控制游戏的全局状态流转。它定义了游戏在任何时刻处于什么状态（菜单、游戏中、暂停、死亡、重开），以及状态之间如何转换。所有其他系统都依赖它来判断"现在该做什么"。

这是一个基础架构系统 — 玩家不会直接感知它的存在，但没有它，游戏就无法运行。

---

## 2. Player Fantasy

玩家不直接感知这个系统。它的存在感为零 — 这是设计目标。玩家只感受到：游戏流畅地响应他们的操作，死亡后能快速重开，没有卡顿或混乱的状态转换。

如果这个系统做得好，玩家永远不会注意到它。如果做得差，玩家会感到"游戏卡了"或"为什么我死了但游戏没反应"。

---

## 3. Detailed Rules

### 3.1 状态定义

游戏有以下 6 个状态：

| 状态 | 描述 | 进入条件 | 退出条件 |
|------|------|----------|----------|
| **MAIN_MENU** | 主菜单，显示标题和开始按钮 | 游戏启动 / 从 GAME_OVER 退出 | 玩家点击"开始" |
| **PLAYING** | 正常游戏状态，玩家可操作 | 从 MAIN_MENU 开始 / 从 REVIVING 复活 | 玩家死亡 / 暂停 / 通关 |
| **PAUSED** | 游戏暂停，时间停止 | 玩家按暂停键 | 玩家取消暂停 |
| **DEAD** | 玩家死亡，去色，显示倒计时 | 玩家生命值归零 | 倒计时结束 / 玩家选择复活 |
| **REVIVING** | 复活选择界面，10秒倒计时 | 从 DEAD 进入 | 玩家选择复活 / 倒计时结束 |
| **GAME_OVER** | 游戏结束，返回菜单 | 从 REVIVING 倒计时结束（不复活） / 从 PLAYING 通关 | 玩家点击"重开" |

### 3.2 状态转换规则

```
MAIN_MENU → PLAYING （玩家点击开始）
PLAYING → PAUSED （玩家按暂停键）
PAUSED → PLAYING （玩家取消暂停）
PLAYING → DEAD （玩家生命值归零）
DEAD → REVIVING （立即，如果有复活币）
DEAD → GAME_OVER （立即，如果没有复活币）
REVIVING → PLAYING （玩家选择复活）
REVIVING → GAME_OVER （10秒倒计时结束）
PLAYING → GAME_OVER （通关最后一层）
GAME_OVER → MAIN_MENU （玩家选择退出）
GAME_OVER → PLAYING （玩家选择重开）
```

### 3.3 状态行为

- **MAIN_MENU**: 游戏循环运行（标题画面动画），不接受游戏输入
- **PLAYING**: 游戏正常运行，所有系统活跃，接受游戏输入
- **PAUSED**: 游戏时间停止（`Engine.time_scale = 0`），UI 仍可交互，显示暂停菜单
- **DEAD**: 游戏时间停止，屏幕去色，显示复活币界面
- **REVIVING**: 游戏时间停止，显示 10 秒倒计时，等待玩家选择
- **GAME_OVER**: 游戏时间停止，显示结算界面

### 3.4 输入处理

不同状态下，输入的响应不同：

| 输入 | MAIN_MENU | PLAYING | PAUSED | DEAD | REVIVING | GAME_OVER |
|------|-----------|---------|--------|------|----------|-----------|
| WASD | 忽略 | 移动 | 忽略 | 忽略 | 忽略 | 忽略 |
| 鼠标移动 | 忽略 | 瞄准 | 忽略 | 忽略 | 忽略 | 忽略 |
| 鼠标左键 | 忽略 | 射击 | 忽略 | 忽略 | 复活 | 忽略 |
| ESC/P | 忽略 | 暂停 | 取消暂停 | 忽略 | 忽略 | 忽略 |
| 任意键 | 开始游戏 | 忽略 | 忽略 | 忽略 | 忽略 | 重开 |

---

## 4. Formulas

本系统无数值计算，纯逻辑控制。

状态转换的时间参数：
- 死亡到复活界面延迟：0 秒（立即）
- 复活倒计时：10 秒
- 复活后无敌时间：1.5 秒（由生命值系统处理）
- 游戏结束到菜单淡出：1 秒

---

## 5. Edge Cases

| 场景 | 处理方式 |
|------|----------|
| 玩家在倒计时最后 0.5 秒点击复活 | 立刻复活，不等倒计时结束 |
| 玩家同时按暂停和死亡 | 暂停优先，死亡延迟到取消暂停后处理 |
| 浏览器标签页失焦 | 自动暂停（Web 平台特有） |
| 玩家快速连续点击"开始" | 防抖，只响应第一次点击 |
| 状态转换期间再次触发转换 | 忽略，直到当前转换完成 |

---

## 6. Dependencies

### 依赖
- 无（这是基础层系统）

### 被依赖
- **瞄准系统**: 读取状态判断是否接受鼠标输入
- **生命值系统**: 触发 PLAYING → DEAD 转换
- **关卡/楼层系统**: 触发 PLAYING → GAME_OVER 转换（通关）
- **房间制战斗**: 读取状态判断是否刷新敌人
- **复活币系统**: 控制 DEAD → REVIVING → PLAYING/GAME_OVER 流程
- **UI/HUD**: 读取状态显示对应界面

---

## 7. Tuning Knobs

| 参数 | 默认值 | 范围 | 影响 |
|------|--------|------|------|
| 复活倒计时 | 10 秒 | 5-15 秒 | 决策压力：太短→来不及思考，太长→节奏拖沓 |
| 死亡到界面延迟 | 0 秒 | 0-0.5 秒 | 反馈感：有延迟→死亡感更强，无延迟→快速重开 |
| 标签页失焦暂停 | 是 | 是/否 | Web 体验：失焦暂停是标准行为 |
| 状态转换防抖 | 0.2 秒 | 0.1-0.5 秒 | 防止误触：太短→可能误触，太长→操作延迟感 |

## 8. Acceptance Criteria

### 功能测试
- [ ] 游戏启动后显示 MAIN_MENU 状态
- [ ] 点击"开始"后进入 PLAYING 状态
- [ ] 按 ESC 键暂停游戏，再按 ESC 恢复
- [ ] 玩家生命值归零时进入 DEAD 状态
- [ ] 有复活币时显示 REVIVING 界面和 10 秒倒计时
- [ ] 无复活币时直接进入 GAME_OVER 状态
- [ ] 点击复活后回到 PLAYING 状态
- [ ] 倒计时结束后进入 GAME_OVER 状态
- [ ] GAME_OVER 状态下点击"重开"回到 PLAYING 状态
- [ ] GAME_OVER 状态下点击"退出"回到 MAIN_MENU 状态

### 边界测试
- [ ] 浏览器标签页失焦时自动暂停
- [ ] 快速连续点击"开始"不会重复触发
- [ ] 状态转换期间忽略新的转换请求
- [ ] 暂停状态下死亡事件被延迟处理

### 集成测试
- [ ] PLAYING 状态下 WASD 输入传递给玩家移动
- [ ] PLAYING 状态下鼠标输入传递给瞄准系统
- [ ] DEAD/PAUSED 状态下游戏输入被正确屏蔽
- [ ] 状态转换时 UI 界面正确切换
