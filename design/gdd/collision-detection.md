# 碰撞检测 (Collision Detection)

*Created: 2026-05-07*
*Status: Draft*
*Priority: MVP — Foundation Layer*
*Depends on: 无*
*Depended on by: 生命值系统, 玩家移动, 弹道系统, 敌人 AI, 射击系统, 近战攻击, 房间制战斗*

---

## 1. Overview

碰撞检测系统负责判断游戏世界中的物体是否相互接触。它是所有战斗系统的基础 — 子弹是否命中敌人、敌人是否碰到玩家、子弹是否撞墙，全部由这个系统处理。

这是整个游戏中被依赖最多的系统（7 个系统依赖它），必须稳定、高效、可靠。在 Web 端运行时，弹幕密度带来的碰撞计算量是主要性能瓶颈。

---

## 2. Player Fantasy

玩家不直接感知碰撞检测。它的存在感体现在：子弹精准命中敌人时的即时反馈，敌人子弹擦身而过时的惊险感，以及墙壁阻挡子弹时的战术空间。

如果做得好，玩家会觉得"每一发子弹都值得"（支柱 1）。如果做得差，玩家会感到"我明明打中了但没判定"或"子弹穿墙了"。

---

## 3. Detailed Rules

### 3.1 碰撞层

游戏使用分层碰撞，不同层之间可以/不可以碰撞：

| 层 | 描述 | 可碰撞的层 |
|----|------|-----------|
| **PLAYER** | 玩家角色 | ENEMY, ENEMY_BULLET, WALL, PICKUP |
| **ENEMY** | 敌人角色 | PLAYER, PLAYER_BULLET, WALL |
| **PLAYER_BULLET** | 玩家子弹 | ENEMY, WALL |
| **ENEMY_BULLET** | 敌人子弹 | PLAYER, WALL |
| **WALL** | 墙壁/障碍物 | PLAYER, ENEMY, PLAYER_BULLET, ENEMY_BULLET |
| **PICKUP** | 拾取物（复活币等） | PLAYER |

### 3.2 碰撞形状

| 物体 | 碰撞形状 | 尺寸 |
|------|----------|------|
| 玩家 | 圆形 | 半径 8px |
| 普通敌人 | 圆形 | 半径 8-12px（按类型） |
| Boss | 圆形 | 半径 24-32px |
| 玩家子弹 | 圆形 | 半径 3px |
| 敌人子弹 | 圆形 | 半径 3-5px |
| 墙壁 | 矩形 | 网格对齐 |
| 拾取物 | 圆形 | 半径 6px |

### 3.3 碰撞检测方法

使用 Godot 内置的物理引擎（Area2D + CollisionShape2D）：
- 玩家、敌人、子弹使用 **Area2D** 节点
- 墙壁使用 **StaticBody2D** 节点
- 碰撞形状使用 **CircleShape2D**（圆形）和 **RectangleShape2D**（墙壁）

### 3.4 碰撞事件

当两个物体碰撞时，系统发出信号：

| 碰撞组合 | 信号 | 处理方 |
|----------|------|--------|
| 玩家子弹 vs 敌人 | `player_bullet_hit_enemy(bullet, enemy)` | 生命值系统 |
| 敌人子弹 vs 玩家 | `enemy_bullet_hit_player(bullet, player)` | 生命值系统 |
| 敌人 vs 玩家 | `enemy_touch_player(enemy, player)` | 生命值系统 |
| 任意子弹 vs 墙壁 | `bullet_hit_wall(bullet, wall)` | 弹道系统 |
| 玩家 vs 拾取物 | `player_pickup(player, pickup)` | 复活币系统 |

### 3.5 性能优化

弹幕密度是核心卖点，但碰撞计算量大。优化策略：

- **空间分区**: 使用 Godot 内置的物理引擎空间分区（默认 BVH）
- **子弹对象池**: 子弹不销毁/创建，而是回收/重用（由弹道系统负责）
- **碰撞层位掩码**: 只检测必要的碰撞组合，减少无效计算
- **帧率自适应**: 如果帧率低于 30fps，减少碰撞检测频率（每 2 帧检测一次）

---

## 4. Formulas

本系统无数值计算，纯碰撞判定。

性能预算：
- 同屏最大活跃子弹数：100（目标 60fps）
- 同屏最大敌人数：20
- 碰撞检测帧预算：2ms（16.6ms 帧预算的 12%）

---

## 5. Edge Cases

| 场景 | 处理方式 |
|------|----------|
| 子弹速度极快，穿透薄墙 | 使用连续碰撞检测（CCD）或增加碰撞形状长度 |
| 多个子弹同时命中同一敌人 | 按碰撞信号到达顺序处理，每帧只处理一次伤害 |
| 敌人重叠（生成在同一个位置） | 生成时检测重叠，偏移位置 |
| 玩家卡在墙壁里 | 移动系统处理，碰撞检测只负责检测，不负责推开 |
| 子弹在出生瞬间就与敌人重叠 | 忽略出生帧的碰撞（出生后 1 帧内不检测） |

---

## 6. Dependencies

### 依赖
- 无（基础层系统）

### 被依赖
- **生命值系统**: 接收碰撞信号，应用伤害
- **玩家移动**: 检测与墙壁的碰撞，阻止穿墙
- **弹道系统**: 子弹碰撞墙壁时销毁/反弹
- **敌人 AI**: 检测与墙壁的碰撞，路径修正
- **射击系统**: 子弹生成时设置碰撞层
- **近战攻击**: 近战范围碰撞检测
- **房间制战斗**: 墙壁/门的碰撞管理

---

## 7. Tuning Knobs

| 参数 | 默认值 | 范围 | 影响 |
|------|--------|------|------|
| 同屏最大子弹数 | 100 | 50-200 | 性能 vs 弹幕密度 |
| 同屏最大敌人数 | 20 | 10-30 | 性能 vs 战斗规模 |
| 碰撞检测帧预算 | 2ms | 1-4ms | 性能 vs 精度 |
| 子弹出生免碰撞帧 | 1 | 0-3 | 防止出生重叠误判 |
| 玩家碰撞半径 | 8px | 6-12px | 受击判定大小 |
| 子弹碰撞半径 | 3px | 2-5px | 命中判定大小 |

## 8. Acceptance Criteria

### 功能测试
- [ ] 玩家子弹命中敌人时触发 `player_bullet_hit_enemy` 信号
- [ ] 敌人子弹命中玩家时触发 `enemy_bullet_hit_player` 信号
- [ ] 敌人接触玩家时触发 `enemy_touch_player` 信号
- [ ] 任意子弹撞墙时触发 `bullet_hit_wall` 信号
- [ ] 玩家接触拾取物时触发 `player_pickup` 信号
- [ ] 不同层之间不产生错误碰撞（玩家子弹不命中玩家）

### 性能测试
- [ ] 100 个子弹 + 20 个敌人时帧率 ≥ 60fps
- [ ] 碰撞检测耗时 ≤ 2ms
- [ ] 子弹对象池正常工作，无内存泄漏

### 边界测试
- [ ] 子弹出生瞬间不与发射者产生碰撞
- [ ] 快速移动的子弹不穿透墙壁
- [ ] 多个碰撞同时发生时全部正确处理
- [ ] 碰撞层设置正确，无跨层误判
